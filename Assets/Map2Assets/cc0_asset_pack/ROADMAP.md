# ModKit roadmap

## What this pack is actually for

The pack is not competing on mesh count. It exists to **absorb usage cost that
would otherwise be paid by every person building a world.**

The intended flow is: someone points their AI agent at this repo, and the agent
already has what it needs to stand up a playable world — so that person spends
their budget on their game instead of on generating props, and on debugging
objects their agent placed floating half a metre above the ground.

That framing decides the ordering below. **The bottleneck is not how many
assets exist. It is how much an agent has to guess.** Every guess is a
round-trip: a render, a screenshot, a correction, another build. Forty assets an
agent can place correctly on the first attempt are worth more than two hundred
it has to be corrected on.

## The ordering principle

Rank work by *how much agent back-and-forth it removes*, not by what is missing
from an asset list.

Measured against that, the largest gap in the pack today is not vehicles or
characters. It is that **the pack ships almost no machine-readable data about
itself.** The entire consumable surface is:

```csv
asset,triangles,vertices
SM_Wall_Straight_4m,620,312
```

An agent told "build a workshop from this pack" cannot learn from the repo where
`SM_Wall_Straight_4m`'s origin sits, how tall it is, which face mates with a
corner piece, what height a roof panel belongs at, or which axis it faces. So it
infers. That inference is the floating-object bug, and no number of new assets
fixes it.

### This is already solved next door

`World-Printer-Lab-For-3D-Worlds` carries a connector schema that does exactly
this job — `docs/PART_CATALOG_SCHEMA_V1.md`:

```js
root.userData.partSpec = {
  family: 'wall', category: 'structure', modular: true,
  nominalDims: [2, 0.4, 2], measuredDims: [2, 0.4, 2], grid: 0.5,
  connectors: [/* local position + normal + compatible kind */]
};
```

It derives connectors from *measured grounded bounds*, snaps only when two
connector normals are nearly opposite, and refuses to mate parts of different
scales. That is a placement contract. ModKit needs the same one, and the two
repos should share a single version of it rather than inventing two.

## Tier 0 — the placement contract

**This is the whole product thesis. Everything else is worth less until it
exists.**

- `docs/asset_catalog.json`, generated by the build, one entry per asset:
  semantic family and category, pivot convention, measured grounded bounds,
  nominal dims, grid module, facing axis, and a socket list carrying local
  position, normal and a compatible-kind tag.
- Sockets derived from geometry at build time, not hand-authored, so they can
  never drift from the mesh.
- `scripts/validate_placement.py` — takes a layout (same shape as
  `examples/industrial_outpost/layout.json`) and reports: objects not touching
  the ground or their support, objects interpenetrating, objects off the grid
  module, sockets connected to incompatible kinds, and mirrored/rotated pieces
  whose pivot has moved them off alignment.
- `AGENTS.md` gains a consumer section. Today it explains how to *contribute*
  assets; it says nothing about how to *place* them.

**Why first:** this is the one deliverable that removes an entire class of
failure rather than adding surface area. It also makes every later tier
self-validating — a new road piece that ships sockets is placeable immediately.

## Tier 1 — collision and layering

- Authored `UCX_` collision per asset. There is currently none, so every
  consumer is silently on auto-convex, which is wrong for doorways, arches,
  stairs and railings — an agent will place a doorway the player cannot walk
  through and have no way to detect it.
- Simple/complex collision split, and per-asset guidance on which to use.
- Collision channel and layer presets for UE and Unity: what is world static,
  what blocks navigation, what is a trigger.
- Navmesh sanity pass on the example scene, so "can the player actually walk
  here" is a checked property.

## Tier 2 — roads, sidewalks, ground

Cheapest procedural work in the whole plan and the largest step toward
something that reads as a *world* rather than a building.

- Road: straight, corner, T, 4-way, curve set, ramp, dead end.
- Sidewalk with kerb, crossings, corner returns, kerb cuts.
- Ground: concrete pad, gravel, dirt, grating, catwalk.
- Traversal: ladder, ramp, stair variants (L-turn, half-landing, open-tread).

Roads are where socket compatibility pays off most — a road network an agent
assembles wrongly is immediately obvious, and immediately validatable.

## Tier 3 — housing and building expansion

- Residential wall set distinct from industrial: siding, plaster, brick, framed
  windows with actual glass (`M_Glass` is defined in `modkit_lib.py` and used by
  nothing).
- Openings that work: glazed window, door leaf that swings, garage/roller door.
- Junctions: inner-corner trim, column caps, wall-to-floor trim. This is what
  stops assembled kits showing seams.
- Interior dressing: shelving, workbench, lockers, pipe elbows and tees (there
  is currently one straight pipe run and no way to turn a corner).
- A second theme. Everything today is one industrial look.

## Tier 4 — vehicles as modular parts

Modular parts, not finished vehicles — matching the "parts are recipes,
finished objects are blueprints" rule already established in World Printer Lab,
which has chassis, wheel assembly, tire and axle recipes to port rather than
reinvent.

- Chassis, wheel, tire, axle, bumper, door panel, bed/tray, cab.
- A utility/industrial vehicle set. A procedurally generated *consumer car* that
  looks good is a much harder problem and is not what this pack should attempt.
- Attachment sockets so a chassis and a wheel assembly mate correctly, which is
  the same Tier 0 machinery.

## Tier 5 — characters

**Flagged as an open decision, not a queued task.** See below.

## Open decisions

### Characters conflict with two of the pack's own rules

The pack's constraints are "every mesh is produced by script" (`AGENTS.md`) and
"public domain, CC0, commercial use, no attribution" (`README.md`). A usable
player character satisfies neither easily:

- **It is not a mesh problem.** A character needs a skeleton, skin weights and
  animation. `bmesh` scripting produces an unrigged capsule figure — which is
  exactly the "looks like something for kids" result already rejected for this
  pack.
- **Licensing is the harder trap.** Most free character bases and animation
  libraries are GPL, CC-BY or custom-licensed, not CC0. MakeHuman/MPFB is GPL.
  Mixamo animations are licensed, not public domain. Pulling any of these in
  would quietly end the pack's CC0 claim, which is one of its strongest selling
  points.

Three honest options:

1. **Descope.** Ship a correctly-scaled player *proxy* plus attachment sockets
   and a documented eye height, and state plainly that the pack does not provide
   characters. Costs nothing, claims nothing false, and still fixes scale
   guessing — which is a real source of agent error.
2. **Conform to an existing open rig standard** and ship CC0 proxy meshes that
   fit it, so consumers bring their own animations. Moderate work, no license
   risk, genuinely useful.
3. **Separate repo, separate licence.** Characters live outside ModKit so the
   CC0 guarantee here stays intact.

### Other decisions worth making explicitly

- **Textures.** The pack currently ships eight flat colour/roughness/metallic
  materials and no maps. "No textures needed" is a stylistic position; it is
  also what keeps the pack reading as blockout to a buyer. UV0 is now uniform at
  2.0 m per repeat, so a trim sheet and tiling PBR sets are unblocked whenever
  this is decided.
- **Rubble and debris are still jittered boxes.** Their shading is now correct,
  but the technique is a blockout one. They need rebuilding as real chunk
  geometry.
- **No Unity-side import script.** `ue_import.py`, `ue_lods.py` and
  `ue_validate.py` exist; the Unity and three.js paths are documentation only.
- **Scale of ambition vs. procedural constraint.** Housing, roads and modular
  vehicle parts all suit script generation well. Organic and character work does
  not. Worth deciding whether the "everything is script-generated" rule is a
  principle or a preference before Tier 4/5 forces the question.

## Summary

| Tier | Work | Removes |
| ---- | ------------------------------- | ------------------------------------------- |
| 0 | Placement contract + validator | Floating, intersecting, misaligned objects |
| 1 | Collision + layering | Unwalkable doorways, wrong convex hulls |
| 2 | Roads, sidewalks, ground | "It's a building, not a world" |
| 3 | Housing + building expansion | One theme, no glass, no junction trim |
| 4 | Modular vehicle parts | No vehicles at all |
| 5 | Characters | No player — pending a licensing decision |

Tier 0 is the one that changes what the pack *is*. The rest is coverage.
