# 原神风格射击游戏 Demo —— 技术设计文档

> 项目：Unity 第三人称射击 + 原神式动作系统，配套自研 C# TCP 服务器
> 本文档用于面试展示与技术复盘：讲清架构、设计模式与核心系统，以及为什么这么设计。

## 1. 项目概述

一个可完整游玩的 3D 动作射击 Demo，包含：

- 登录 / 注册 / 云存档（自研 C# TCP 服务器 + SQLite）
- 原神式移动：冲刺、闪避（无敌帧）、滑铲、攀爬、下蹲 + 体力系统
- 武器系统：多武器、弹匣换弹、枪械模型切换、词条（装饰者模式）
- 战斗：子弹/火花对象池、伤害数字、**责任链伤害结算**、暴击
- 敌人 AI：行为树（含自研 GraphView 图编辑器），感知节流
- 内容：迷宫战斗地图（机关门 + 波次刷怪）、宝箱、委托任务、商店、对话
- **程序化迷宫**：DFS 回溯算法随机生成迷宫试炼

## 2. 总体架构

```
┌────────────────────────── 客户端 (Unity) ──────────────────────────┐
│ 表现层: UI(背包/角色/商店/对话/HUD)  ←── 事件驱动(EventHandler) ──→ 逻辑层 │
│ 逻辑层: GameManager / InventoryManager / QuestManager / ShopManager    │
│ 战斗层: 玩家状态机 / 武器系统 / 伤害责任链 / 敌人行为树                 │
│ 网络层: GameClient (TCP) + CloudSaveManager (云存档)                   │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ TCP 自定义协议 (4字节长度+4字节消息ID+JSON)
┌──────────────────────────────┴─────────────────────────────────────┐
│ 服务器 (C# .NET)  MVC 分层                                          │
│ Controller(消息分发) → Service(注册/登录/存档) → Repository(SQLite)  │
└────────────────────────────────────────────────────────────────────┘
```

## 3. 设计模式应用清单

### 3.1 单例模式

- 位置：`SingleMonoBase<T>` 基类、`GameManager`、`InventoryManager`、`AudioManager`、各懒加载 UI（Toast/委托追踪/地区提示/残血红闪/加载视频）
- 说明：场景级单例（UIManager 等）与跨场景懒加载单例（自动创建 + DontDestroyOnLoad）两种形态
- 面试点：能讲清“为什么懒加载”“重复实例如何销毁”“场景切换后静态引用失效如何自愈”

### 3.2 状态机（策略模式的变体）

- 位置：`PlayerModel.SwitchState` + `PlayerStateBase` 派生类（Idle/Move/Aim/Climb/Dodge/Slide/Crouch）；敌人 `EnemyBase` 状态
- 说明：每个状态一个类，行为通过 `Enter/Update/Exit` 封装，状态切换只改指针
- 面试点：状态扩展不需要改主流程，符合开闭原则

### 3.3 观察者（事件总线）

- 位置：`EventHandler` 静态事件 + `CallXxxEvent` 封装，UI 订阅
- 说明：血量/体力/弹药/背包/委托变更全部事件驱动，避免每帧轮询 UI
- 面试点：`?.Invoke` 空安全、事件订阅/退订配对（OnEnable/OnDisable）、解耦

### 3.4 对象池

- 位置：`BulletPool`（子弹/火花）、`DamageNumberUI`（伤害数字）、`AudioManager`（音效播放器池）
- 面试点：避免高频 Instantiate/Destroy 的 GC 与卡顿；预生成 + 回池复用

### 3.5 享元模式（数据共享）

- 位置：`WeaponData_SO` / `FoodData_SO` / `MaterialData_SO`（ScriptableObject 配置表）
- 说明：一份配置被所有实例共享，运行时缓存查询结果（Dictionary）

### 3.6 模板方法

- 位置：`EnemyBase`（Hurt/Update/FindAttackTarget 虚方法）+ 子类覆写（丘丘人/石头人/史莱姆）

### 3.7 MVC

- 位置：服务器端 Controller/Service/Repository 分层

### 3.8 装饰者模式（武器词条）★ 新增

位置：`Assets/Scripts/Item/WeaponStatProvider.cs`

**问题**：武器属性（攻击/射速/弹匣/暴击）需要支持任意组合的词条加成，且要容易扩展。

**方案**：

```csharp
IWeaponStatProvider（接口）
  ├─ BaseWeaponStatProvider（读武器模板，无加成；基础暴伤 50%）
  └─ WeaponAffixDecorator（包裹上一层，修正某一项属性）
        组装: 基础 → 词条1 → 词条2 → ...（洋葱式链）
```

- 词条表：锋利(+10%攻击)、狂热(+15%射速)、扩容(+8弹匣)、精准(+10%暴击率)、致命(+50%暴伤)
- 获得武器时按星级随机 1~2 条；词条随本地存档与云存档持久化（打包进背包 JSON，服务器协议不变）
- 新增词条 = 往表里加一行 + 在装饰器加一个分支，主流程不用动

**面试点**：开闭原则（对扩展开放、对修改关闭）；运行时动态组合；与“直接 if 判断”的对比。

### 3.9 责任链模式（伤害结算）★ 新增

位置：`Assets/Scripts/Combat/DamagePipeline.cs`

**问题**：伤害流程未来要不断加机制（护甲、抗性、护盾、元素克制、吸血……），不能每次改主流程。

**方案**：

```csharp
IDamageModifier（接口） → 各环节实现 Process(DamageContext)
DamagePipeline.Resolve(ctx) 依次执行:
  基础伤害 → 暴击(暴击率×暴伤) → 护甲(固定减伤) → 抗性(百分比减伤)
```

- `DamageContext` 是所有环节共享的数据（基础伤害/最终伤害/暴击率/暴伤/护甲/抗性/是否暴击）
- 玩家打敌人、敌人打玩家走同一条链；暴击数字用黄色大字 + 更大字号显示
- 加新机制 = 实现 `IDamageModifier` 并 `Add` 进链，主流程零改动

**面试点**：单一职责、可插拔、职责链的“请求传递”思想。

### 3.10 行为树

- 位置：`Assets/Scripts/AI/` 运行时 + `Assets/Editor/BehaviorTreeGraph/` GraphView 图编辑器
- 流程：编辑器可视化编辑 → 导出 JSON → 运行时加载执行；支持序列/选择/条件/动作节点
- 面试点：AI 决策与表现解耦；自己实现了编辑器拓展（GraphView），从数据到运行时的完整链路

## 4. 核心系统详解

### 4.1 玩家动作状态机 + 体力

- 状态：Idle / Move / Aim / Climb / Dodge / Slide / Crouch
- 体力：冲刺/攀爬/闪避消耗，走动不消耗；升级提升上限（每级 +10）
- 闪避带无敌帧（`SetActiveRoleInvincible`），滑铲 = 移动中 Shift+Ctrl

### 4.2 武器系统

- 数据：`Weapon` 模板（攻击/射速/弹匣/模型挂点/子弹/火花/枪声）+ `WeaponItem` 实例（词条）
- 换弹：打空自动换弹 + R 手动；换弹期间不能开火（HUD 显示装填中）
- 模型：装备切换时在 `DEF-hand.R` 下生成枪械模型，Animation Rigging 左手 IK 扶枪，数据驱动挂点
- 伤害来源：`PlayerWeapon.RefreshWeaponData` 用装饰者链计算最终属性 → 写入子弹 → 敌人受击走责任链

### 4.3 伤害结算流程

```
开枪 → 子弹(携带伤害/暴击率/暴伤) → 命中敌人 EnemyBase.Hurt
  → DamagePipeline: 暴击判定 → 护甲减伤 → 抗性减伤
  → 扣血 + 伤害数字(暴击黄色大字) + 受击动画/音效
敌人攻击玩家 → GameManager.ApplyDamageToActiveRole → 同一条链(护甲=角色防御)
```

### 4.4 敌人 AI（行为树）

- 节点：Selector / Sequence / Condition / Action（巡逻/追击/攻击/死亡/自爆）
- 优化：感知 0.2s 节流、寻路 0.3s 节流、动画参数去重（每帧只设置变化过的参数）
- 三种敌人：丘丘人（近战）、石头人（丢石头抛物线弹道）、史莱姆（纯数学弹跳，不依赖 NavMesh，低血自爆/缩壳）

### 4.5 背包 / 装备 / 云存档

- 背包：武器/食物/材料三种物品，按 UID 管理；图标/头像/字体缓存
- 装备：角色 ↔ 武器多对一；云存档额外保存“Equip”记录（角色装备了哪把武器）
- 存档链路：本地 `inventory.bin`（5s 节流 + 异常保护）→ 云 JSON（5s 节流上传）；读档/云导入后自动给旧武器补词条

### 4.6 网络协议

```
帧格式: [4字节消息长度][4字节消息ID][UTF-8 JSON]
消息: 注册(100) / 登录(101) / 拉取玩家数据(200) / 保存玩家数据(201) / 心跳(1)
```

- 异步收发（async/await），收消息线程 → 并发队列 → 主线程 Update 分发，避免跨线程操作 Unity API
- 心跳：客户端每 10s 发送，服务器可及时发现掉线连接
- 服务器 MVC：消息分发（Controller）→ 业务（Service）→ SQLite（Repository）

### 4.7 程序化迷宫生成 ★ 新增

位置：`Assets/Scripts/Combat/MazeGenerator.cs` + `MazeManager.cs`

**算法**：DFS 回溯（递归回溯）生成“完美迷宫”

1. 把地图看成 `房间数×2+1` 的物理格子：房间在奇数列/奇数行
2. 从起点房间出发，随机选一个未访问的相邻房间
3. 打通两房间之间的墙，标记已访问，入栈
4. 无路可走时回溯（出栈），直到所有房间访问完毕

**集成**：

- 安全区出生点前方生成蓝色入口标记 + 触发器；玩家踩入 → 按入口为中心生成迷宫并传送玩家到起点
- 终点（右下角房间）放出口触发器 → 通关发奖励（食物×3）→ 自动清理全部生成的方块
- 墙/地板用“复制 Unity 默认材质”的方式着色，保证任何渲染管线都不出紫材质
- 入口位置可在 GameManager Inspector 配置（固定坐标 / 出生点偏移）

**面试点**：能讲清算法复杂度 O(房间数)、为什么生成的是“完美迷宫”（任意两点唯一通路）、如何与场景/玩家系统解耦。

## 5. 性能优化清单

- 对象池：子弹、火花、伤害数字、音效播放器
- 事件驱动 UI：血量/体力/弹药/背包变更，无每帧轮询
- 节流：AI 感知 0.2s、寻路 0.3s、小地图 0.1s 手动渲染（平时禁用相机）
- 缓存：图标/头像/字体/音效/BGM；加载失败也缓存（不重复加载）
- SetActive 去重（血条/体力条）、存档写盘异常保护、懒加载单例（平时零开销）

## 6. 如何运行

1. 先启动服务器（`shoot-yuanshen-SERVER`，监听 8888）
2. Unity 打开项目，进入 `LoginScene`，Play
3. 注册 → 登录 → 开始游戏
4. 打包：Build Settings 依次添加 LoginScene / SampleScene / BattleMap
